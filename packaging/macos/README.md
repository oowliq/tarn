# Сборка и подпись под macOS

```bash
packaging/macos/build-app.sh [версия]   # dist/tarn.app + dist/tarn-macos-universal.zip
```

## Зачем постоянный сертификат

macOS запоминает разрешения за приложением по его подписи: доступ к паролям в связке ключей
(«Всегда разрешать») и «Универсальный доступ» (перехват ⌘Tab и т.п.). У ad-hoc-подписи нет
сертификата, и каждая сборка для macOS — новое приложение: после каждого обновления она снова
спрашивает пароль связки ключей и сбрасывает «Универсальный доступ».

Если все сборки подписаны одним сертификатом, разрешения сохраняются между обновлениями — на
любой машине, доверять сертификату для этого не нужно.

Предупреждение Gatekeeper при первом запуске скачанного архива это не убирает: для него нужна
нотаризация с Developer ID (платный Apple Developer Program). Встроенное автообновление архив
карантином не помечает, поэтому обновления запускаются без предупреждения.

## Один раз: создать сертификат

```bash
packaging/macos/make-signing-cert.sh
```

Скрипт создаёт самоподписанный сертификат «Tarn Code Signing» на 10 лет, кладёт его в связку
ключей login и пишет в `~/tarn-signing/` файлы для секретов GitHub. Запускать один раз: новый
сертификат — снова «другое приложение» для всех, кто уже установил Tarn.

## Подписанная сборка

Локально:

```bash
TARN_SIGN_IDENTITY="Tarn Code Signing" packaging/macos/build-app.sh
```

При первой подписи macOS спросит доступ `codesign` к ключу — «Всегда разрешать». В конце скрипт
печатает требование подписи; при постоянном сертификате оно вида
`identifier "dev.tarn.tarn" and certificate root = H"…"` и не меняется от сборки к сборке.
Без `TARN_SIGN_IDENTITY` сборка подписывается ad-hoc.

В CI (`.github/workflows/release.yml`) сертификат берётся из секретов репозитория:

| Секрет | Что |
|---|---|
| `MACOS_SIGN_P12` | `tarn-signing.p12` в base64 |
| `MACOS_SIGN_P12_PASSWORD` | пароль от `.p12` |
| `MACOS_SIGN_IDENTITY` | имя сертификата (`Tarn Code Signing`) |

Без секретов (например, в форке) релиз подписывается ad-hoc.

Первый запуск сборки с новой подписью — ещё один запрос пароля связки ключей и повторная выдача
«Универсального доступа»: это смена подписи с ad-hoc на постоянную. Дальше — без запросов.
